# Contributing

1. Open an issue describing the improvement or defect.
2. Keep examples minimal, reproducible, and safe.
3. Prefer normative references over personal conventions.
4. Clearly label recommendations, trade-offs, and optional patterns.
5. Add or update tests when changing runnable examples or OpenAPI contracts.
6. Never commit credentials, real personal data, or production tokens.

Use clear commit messages and submit focused pull requests.
