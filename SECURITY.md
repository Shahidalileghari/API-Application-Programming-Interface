# Security policy

This repository is educational. Do not deploy its demonstration server as-is.

- Report suspected vulnerabilities privately to the repository maintainer.
- Never include real secrets, tokens, customer records, or exploitable production details in public issues.
- Keep dependencies updated and review security advisories.
- Apply authorization checks on the server for every protected object and action.
- Use TLS, secure secret management, input validation, safe logging, and least privilege in real systems.

The sample API has no real authentication or database and must not be treated as a secure production service.
